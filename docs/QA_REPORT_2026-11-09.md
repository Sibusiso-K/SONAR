## Bugs found and fixed

Ordered by how much they mattered to a visitor or to the data.

## Test inventory

**Python (`tests/`, 227 tests).** Shared helpers; `sonar.py` (parsing, next dates, scoring, ICS output including folding and escaping); the migration; `sync_radar` (row building, the guarded delete, the HTTP helper); the forecaster; the scraper's hidden-text and prompt-injection defences; the post-deploy smoke checker, against a fake server that breaks in each way it should catch; CLI behaviour as subprocesses; migration syntax and RLS lockdown; and data integrity (ids, links, scores, tiers, schema with a shrink-only debt list, calendar, and generated-file freshness).

**Web unit (94 tests).** Date arithmetic across the UTC/SAST boundary, collisions, win probability, number and label formatting, URL safety, the rate limiter, conversation fitting, security headers, the splash boot script (executed against fake browser globals) and transition direction.

**Browser (71 passed, 5 skipped by design (76 scenarios)).** Run against the production build with a mocked database whose rows come from the real `sync_radar.build_rows()`: splash behaviour (first visit, repeat visit, click and key skip, reduced motion, blocked storage, dark theme before first paint), every section on desktop and phone, sidebar navigation and back/forward, direction-aware view transitions, error states, hostile data, link safety, the assistant and its rate limit, security headers, bundle secret scan, and horizontal overflow.

## Coverage and known gaps

Python line coverage is **55%** overall: 98–100% on the shared helpers, migration and smoke test, 78% on the live sync. Low coverage is concentrated in code that talks to live services: the Supabase commands in `sonar_db.py` (36%), the Groq and fetch loop in `watch_sources.py` (40%), `build_team_profile.py` (0%, GitHub API only). These rely on the guards above and on manual runs.

Not tested, and worth knowing:

- **Chromium only.** Firefox and Safari are untested. The View Transitions API is Chromium and Safari 18+; the fallback animation is unverified in Firefox.
- **No accessibility automation** (axe) and **no visual-regression baseline**. The animations were checked by reading rendered frames, not by a pixel test.
- **The live database.** Row Level Security and the actual data were not inspected; see O-1 in the [security review](SECURITY_REVIEW_2026-11-09.md).
- **Real assistant answers.** The tests cover the endpoint's behaviour (limits, errors, size handling), not the quality of a model's answer.
- **Load.** No load or soak test. The assistant's limits are per server instance.
- **Production request logs.** Vercel's Hobby plan keeps one hour of runtime logs, so only the 7-day error summary (no errors) could be read.

## Observations not fixed

- 27 entries carry an old `prize` shape; the assistant prints their breakdown as `[object Object]`. Tracked by the shrink-only `LEGACY_SCHEMA_DEBT` list.
- Nothing automatically moves an entry to `past` when its deadline goes by. Several entries sat at `open` for days after closing. A scheduled check that opens an issue would close this.
- `RSNA Knee`, `BCG Platinion` and `Mintek-SCi` are past their dates with outcomes not recorded.
