# SONAR repository review

Reviewed 14 September 2026 at commit `082b0b3`. Scope: repository architecture, application routes and shared logic, data transformation, discovery, database migrations, CI, calendar, operational documentation and War Room. This is a repository-wide risk review, not a claim that every generated UI component or external integration was exercised.

**Assessment:** the app builds and type-checks, but deadline correctness, discovery completeness and evidence integrity need fixes before SONAR can be treated as a dependable operational system. The War Room is useful briefing material; it is not yet a verified readiness tracker.

## Prioritized findings

### 1. P1 — Calendar dates shift by one day in South Africa

`web/src/components/EventCalendar.tsx:104` converts local midnight to UTC before looking up an ISO calendar date. In `Africa/Johannesburg`, the cell labelled 17 September produces `2026-09-16`, so an event keyed as 17 September renders in the 18 September cell. Reproduced with the runtime using the project's timezone. `web/src/lib/analytics.ts:131` makes the same conversion for Monday week labels and labels them Sunday.

**Fix:** use local year/month/day keys consistently for date-only values. Add timezone tests for Johannesburg and UTC, covering month boundaries and collision labels.

### 2. P1 — Discovery excludes new events on known source pages

`scripts/watch_sources.py` assigns the source listing URL to every observation's `candidate_url`. `scripts/sonar_db.py:571` then excludes every observation whose URL already appears in any tracked event's links. The purge at line 600 also removes those URLs from the ledger.

An unseen event on Geekulcha's existing events page is therefore discarded precisely because SONAR already monitors that page. A mocked new-event observation reproduced an empty candidate ledger. This is broader than deduplicating the event already on the board.

**Fix:** retain source URL separately from event identity; deduplicate by resolved event URL or an evidence-backed event/edition key. Preserve unmatched mentions for review and do not purge a whole listing page. Test two different events from one source, including a previously dismissed event followed by a new edition.

### 3. P1 — Public audit inserts permit forged authoritative updates

`web/supabase/migrations/20260811105003_4fbab8fb-3259-465c-8a42-99f445dacaa9.sql:61–65` grants anonymous INSERT on `updates` with an unrestricted check. The alternate `app` schema repeats this in `supabase/migrations/0004_app_schema_for_website.sql:119–123`. The later lockdown migration intentionally leaves it unchanged.

An anonymous caller can choose actor, actor kind, summary and timestamp; `/updates` displays them as attributed history, and the assistant reads recent rows into its system context. Append-only prevents erasure but does not establish authenticity. The open watchlist is an explicit product tradeoff; forged verification history is a separate integrity defect.

**Fix:** restrict authoritative audit writes to trusted server/CI code. If anonymous watch actions remain, accept only that narrow operation and derive the audit fields server-side, marking the identity as unverified. Keep user-supplied audit text out of trusted model instructions. Static schema finding; production grants were not inspected or exploited.

### 4. P1 — War Room understates GovTech's output ownership terms

`web/src/routes/war-room.tsx:87` describes a licence over Hackathon Outputs. The official terms also contain an assignment of rights in those outputs in clause 4.2.1. Clauses 4.2.2–4.2.3 address retained Background IP and the licence when incorporated. This is material to what reusable code the team chooses to bring.

**Fix:** replace the incomplete summary with clause references and prepare a component/IP inventory before use. The public PDF also still says 17–19 September; the repository records a later selection email extending the event through 20 September. Preserve both sources and obtain the latest written schedule. [Official GovTech terms, checked 14 September](https://www.govtech.gov.za/wp-content/uploads/2026/07/GovTech-2026-Hackathon-Terms-and-Condition.pdf).

### 5. P1 — Preparation claims exceed the evidence held here

`web/src/routes/war-room.tsx:85` says nearly three weeks between selection on 9 September and kickoff on 17 September; that is eight days, with three days remaining at this review. Line 120 presents rare-class recall as already reported, whereas `data/hackathons.json` describes an abstract commitment to report it. This checkout contains no event deliverables under `entries/`, only placeholders; prototype metrics and TRL 4 completion cannot be verified here.

**Fix:** record evidence links, owner, checked-at time and state for every readiness item. Distinguish submitted plans from demonstrated capability. Keep RSVP as “confirmation evidence missing,” not proof that no reply was sent. The roster names for Lethabo differ across event records and need reconciliation, not automatic merging.

### 6. P2 — Database failures masquerade as empty results

`web/src/routes/index.tsx:35,156` defaults query data to an empty array and displays an empty-board message after a query failure; the query hook throws but the route does not render the error. Radar, Stats and Updates follow similar patterns. `web/src/lib/assistant.functions.ts:87` discards Supabase error fields and can ask the model to reason from an empty board following a database error.

**Fix:** distinguish loading, error, stale cached data and confirmed empty results; provide retry. Stop assistant generation when required board reads fail. Verify with a rejected query and a successful empty response.

### 7. P2 — Operational deadlines and exported calendars drift

`scripts/migrate_to_opportunities.py` considers a fixed set of deadline keys and excludes `confirm_attendance_by`. A mock RSVP on 15 September with kickoff on 17 September returns the kickoff date. The actual overdue GovTech RSVP survives only in the narrative War Room.

`scripts/sonar.py:231` exports `data/calendar_events.json`, not the main board. That file has no dedicated Geekulcha or Mintek event entries and still describes GovTech as 17–19 September with unresolved eligibility. Its all-day end of 20 September is exclusive, omitting the 20th recorded in the later email. CI does not regenerate this calendar.

**Fix:** model event milestones as structured records with owners, due times, confidence and completion evidence. Generate calendar and War Room from those records, preserving exclusive end dates. Include overdue unfinished milestones and mandatory conference attendance.

### 8. P2 — Failed or skipped pipelines can report success

`.github/workflows/refresh-board.yml:123,143` exits zero when destination credentials are absent, even while logging an error. `scripts/watch_sources.py:395` writes `ok: True` after page-fetch failures are skipped; model HTTP errors return an empty result as well. A run can therefore be green without reading sources or updating the live board.

**Fix:** fail required sync steps; represent optional skipped destinations explicitly. Count fetched, failed and extracted sources, and distinguish extraction failure from a valid zero-candidate page. Emit partial/failed status when appropriate and verify the persisted destination revision after syncing.

### 9. P2 — “Validate against the schema” does not use the schema

The CI step checks only duplicate IDs, names, confidence presence and JSON syntax. `schema/hackathon.schema.json` excludes current statuses such as `selected`, `registered` and `submitted`, while the generated board points at an individual-record schema despite containing a document wrapper.

**Fix:** define separate source-record and generated-document schemas, reconcile current states, validate dates and ranges before writes, and fail on inconsistent scores. Current weighted scores are correct; the validation coverage is the issue. Full JSON Schema validation was not executed because the bundled runtime lacks `jsonschema`.

### 10. P2 — Current Geekulcha brief is missing from the War Room

`web/src/routes/war-room.tsx:98` reasons from the 2025 theme. The current organiser page specifies **Build for Use**, with identified users, a validated problem, security, sustainability and measurable impact. Its public subtheme list differs from the repository's recorded Blockchain for Impact track; confirm the selected track rather than silently changing it. The selection-email request for TRL 4 remains a separate, later requirement reported by the repository. [Official 2026 event page, checked 14 September](https://sonke.gklink.co/event/gkhack26).

**Fix:** use the current brief, link the selection feedback, and map each requirement to a demo or evidence artifact. Remove absolute claims that a sharper pitch wins “every time” and unsupported ordering of Mintek judging criteria.

## Additional follow-ups

- `Assistant.tsx` sends the complete growing conversation; the server accepts at most 24 messages. The thirteenth user message exceeds the limit, and further retries only grow the invalid payload. Trim bounded history or offer a reset, preserving relevant context.
- The anonymous AI endpoint has input limits and CSRF protection but no application-level rate budget. Verify deployment-level limits before relying on them; they were not inspected here.
- `watch_sources.py:343` checks quote presence, but not whether the extracted value is contained in the quote or the field belongs to the allowed vocabulary. Add structured validation; quote presence proves provenance of a span, not correctness of every associated claim.
- Expected value multiplies the whole prize pool by a heuristic probability. Treat it as a ranking index, not an expected payout; use award-level outcomes if financial estimates are required.
- README, TEAM and STATUS contain dated or conflicting operational claims. STATUS includes historical conclusions superseded later in the same file. Publish one dated current-state summary with explicit historical notes.
- `migrate.yml` only resolves root migrations, while the app lockdown migration lives under `web/supabase/migrations`. Document and validate the correct project/path before running DDL. Avoid direct workflow-input interpolation into shell code.
- The assistant prompt and identity selector describe two operators; War Room says a team of three. Preserve event-specific rosters rather than implying that all three attend every event.

## Validation performed

- Locked Bun dependency installation succeeded after using an accessible cache and network permission.
- `bun run build`: passed; local build produced the default Cloudflare-target output. This does not establish the production Vercel deployment configuration.
- `tsc --noEmit`: passed.
- Standard lint: failed with 10,886 formatting errors and seven warnings in the Windows checkout, including widespread CRLF findings. With only the Prettier rule disabled, ESLint reported zero errors and seven warnings. Formatting failures are not represented as runtime defects.
- Every Python script parsed; every data JSON file parsed; source IDs were unique; all 23 weighted scores matched.
- Sync dry construction produced 23 opportunity rows, three past rows and 51 audit rows. No database writes were made.
- Regeneration ran in a scratch directory. Fourteen generated entries differed from the checked-in snapshot; time-derived fields are expected to change and this alone is not evidence of a production outage.
- Reproduced the timezone lookup error, dropped new event from a known source page, and ignored RSVP milestone.
- Build-generated route-tree changes were restored. No fixes, commits, pushes, deployments, registrations or messages were made.

**Limits:** no production credentials, database policy inspection, live CI run inspection or browser interaction was performed. Official GovTech and Geekulcha pages were read; the Mintek conference URL did not load through the research tool. Private selection emails, submitted PDFs and external competition repositories were not available in this checkout, so claims about their contents remain repository-reported.
